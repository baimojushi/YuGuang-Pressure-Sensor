# 余光 Web App

共用一套前端与业务逻辑，提供正式使用与展示两个入口。采用 10 月 29 日确认的交互：心意可等待、灯语一轮后淡出、主动回执、双向回应、自由休息、本人呼吸采集与练习记录。

队友交接从 [交接面板](handoff/index.html) 与 [灵机一动接入说明](docs/队友交接与灵机接入.md) 开始。App 和业务接口已实现，灵机平台适配与真机联调尚未完成；不要把当前 App 设备绑定当作灵机配网绑定。Postman 请求模板在 `handoff/`。提交代码后可运行 `python3 scripts/package-handoff.py` 生成不含本地数据与密钥的源码交接 ZIP。

## 两个入口

| 版本 | 在线地址 | 数据与登录 |
| --- | --- | --- |
| 正式版 | https://yuguang-emotional-presence.red-rice-3957.chatgpt.site/ | 用个人平台身份登录，首次填写自己的称呼；无默认用户、设备、配对、消息或呼吸记录 |
| 展示版 | https://yuguang-emotional-presence.red-rice-3957.chatgpt.site/demo | 仅这里提供小满、阿屿和模拟灯，测试数据与正式版隔离 |

本地正式版 http://localhost:3100/ 使用自己注册的账号与密码（至少 12 位）。同一台电脑测试两人：第一个账号在“亲友连接”点“打开另一个账号”，第二个标签页注册 / 登录另一账号，再通过邀请码配对。按钮使用独立标签页会话；不要通过复制已登录标签页来切换账号。线上平台身份会在同一浏览器登录中共享，同一 ChatGPT 身份开两个标签页仍是一个人。本地展示版 http://localhost:3100/demo 自动进入示例身份，可切换，也可分别开 /demo?as=sender 与 /demo?as=receiver 两个标签页。

## 启动

需要 Node.js 22.13 或以上版本。

~~~sh
npm ci
npm start
~~~

正式版首次使用：自己注册或平台登录 → 填写称呼 → 任一方生成邀请码，另一方输入 → 双方互发心意。不需要预选身份，也不需要先绑定玩偶。每人可按需在“我的余光”绑定自己的一台设备，生成设备编号和一次性密钥，配置到自己的硬件固件。双方各有玩偶时，各自的玩偶只接收发给本人的灯语；比赛真机验收仍先走通单台玩偶。

没有硬件时正式版仍可使用真实配对、消息、上传/回听原声、呼吸练习与自由休息计时；设备保持“等待设备心跳”，呼吸采样为空，不模拟在线或生成测量值。

## 一处修改 两版同步

- public/：两版使用的同一套页面、呼吸练习、统计与导出。
- shared/service.mjs：所有存储后端共用的授权、配对、队列、回执、休息、设备协议。
- shared/backend.mjs 与 shared/supabase.mjs：正式版可选 Supabase PostgreSQL / 私有音频存储；展示版保持原隔离存储。
- server.js：仅负责本机 HTTP 和 SQLite/文件适配。
- adapters/：线上薄适配、页面入口与追加式数据库 schema。
- hosting/：自动生成的部署源副本，不要单独修改其业务文件。
- scripts/sync-hosting.mjs：同步并校验，防止本地与部署文件漂移。

~~~sh
npm test
npm run check:sync
npm run sync:hosting
~~~

npm test 会先自动同步部署文件。开发与发布到已有 Sites checkout 时：

~~~sh
node scripts/sync-hosting.mjs --site ../yuguang-online
~~~

同步的是源码；线上仍需按 Sites 流程构建、保存版本并发布，不把“代码同步”当作“已上线”。数据库迁移应在 Sites checkout 运行 npm run db:generate，检查生成 SQL，保留已应用的旧迁移。后续两版功能修改只改 public/ 与 shared/，两版的行为通过服务端 mode 分离。

## 数据隔离与保留

本地默认存储在 data-v2/live.sqlite、data-v2/demo.sqlite，原 data/ 中的旧版数据不删除，也不导入正式版。可用 DATA_DIR 指定新的持久化目录。

正式版可通过 LIVE_STORAGE=supabase 切换到专用 Supabase 项目，使用 public.yuguang_spaces 的 live-v2 状态和 yuguang-audio 私有桶。启用前的默认后端是 SQLite / D1；配置启用后连接失败会报错，不会回退写另一份数据。展示版仍使用独立 SQLite / D1 与 R2，不进入 Supabase。旧数据保留，不自动导入正式库。正式空间不调用任何示例 seed。展示身份/密钥不能用于正式接口；正式接口没有模拟硬件入口。实际启用与真实云端检查见 docs/验收记录.md。

2026-10-30 本机正式配置与线上第 5 版均已启用专用 Supabase 项目 yuguang-live，数据库和私有音频真实读写检查通过。新克隆的仓库仍须自行配置被忽略的 .env；不会携带服务端密钥。

线上正式账号依赖 Sites 可信身份头；正式配对允许两个不同个人身份跨端连接。示例身份只用于展示空间。本地密码使用独立盐的 PBKDF2-SHA256 保存，登录失败限流。设备只保存密钥哈希，绑定或轮换时显示明文一次。

当前是黑客松规模的真实持久化实现，使用 CAS 事务保存每个空间的聚合状态，单空间上限 8 MiB、账号上限 1000；不是大规模服务架构。可用记录导出，容量不足会明确报错，不静默覆盖。

## 持续呼吸采集

桌搭定位为开机后持续采集，无需用户按开始或抱住触发。App 的「我的呼吸」顶部提供当前频率、近五分钟频率趋势、采样时间与无信号 / 中断状态。设备或经核验的平台适配层调用 `/api/hardware/:deviceId/breathing/live`，页面关闭时后端仍接收并自动分段保存，详见 [持续采集协议](docs/持续呼吸采集.md)。当前仅接收已计算频率，未收到的模型、真机传感器和灵机平台接入仍待队友完成。没有真实上报则显示等待，不生成实时测量。
