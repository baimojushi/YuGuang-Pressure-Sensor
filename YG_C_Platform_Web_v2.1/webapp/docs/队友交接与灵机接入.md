## 本地运行与两人测试

安装 Node.js 22.13 或以上版本，在 `yuguang` 文件夹中打开终端：

```sh
npm ci
npm start
```

打开 http://localhost:3100/ 。新解压版本没有 `.env`，默认用本机 SQLite，正式空间从空数据开始；不会自动连组织的 Supabase。注册自己的账号（密码至少 12 位），在“亲友连接”点“打开另一个账号”，用第二个账号配对。不要复制已登录标签页来切换人。展示空间为 http://localhost:3100/demo 。

数据留在 `data-v2/`，不要发给其他人。服务器已监听局域网；同一 Wi-Fi 下手机可访问电脑局域网 IP 的 3100 端口（需要电脑防火墙允许）。`localhost` 只指当前设备，不能把它发给远端队友。不要把这个开发服务器直接暴露公网。

线上正式身份目前由 Sites / ChatGPT 提供，本地使用独立账号密码；不是 Supabase Auth，两个身份体系也不会自动合并。本地账户与云端账户不是一套。正式云端的数据库和私有原声已接 Supabase；ZIP 不带数据库、账号、语音、服务端密钥或已绑定设备密钥。

## 接入路线（待实现）

```text
亲友 App → 余光后端（配对、队列、权限、Supabase）
                    ↓ 待开发的平台适配层
              灵机一动产品 / 设备控制 → 官方 SDK → 真机灯效
                    ↑ 平台事件 / 回调             ↑ 触摸
              余光后端（执行状态、主动回应） ←──────┘
```

箭头表示目标路线，不表示已经接通。App 的“绑定玩偶”当前只在余光生成设备编号和独立密钥，不能替代灵机小程序的配网和真实绑定。需要经服务端核验后保存“余光设备 → 灵机 PID / SN”的归属映射；只输入别人 SN 不得获得控制权。

平台适配层需补：服务端调用平台控制能力、平台凭证管理、绑定归属核验、回调验签及防重放、平台事件映射、幂等重试、解绑后的失效处理。若平台仅支持特定 SDK / 小程序接口，按官方支持方式调整，不能预设网站可直接调用。

### 拟议物模型（项目设计，非官方导入文件）

| 项目字段 / 动作 | 建议类型 | 语义 |
| --- | --- | --- |
| focus、power | 属性 | 专注、情感光开关；同步真实设备状态 |
| play_light | 服务 | 携带 commandId、intent、颜色、亮度、周期、次数、截止时间，执行一轮淡出 |
| stop_light | 服务 | 专注、关灯、休息或解绑时停止情感光 |
| light_accepted / light_finished | 事件 | 只表示设备执行；不能作为用户已读 |
| short_touch / long_touch | 事件 | eventId 幂等；长触至少 5 秒，同一次动作不能兼发短触 |
| focus_changed | 事件 | 硬件改变专注状态时回传 |
| breathing_sample | 事件（有传感器才启用） | 真实测量记录；无传感器保持空白，不推算呼吸 |

最终 identifier、类型和参数须在平台创建产品后与固件共同确认。现有 `/api/hardware/...` 接口可作为平台适配层的业务语义参考；不能未经鉴权就把平台回调转发成设备事件。

## 双方分工与需要回传的信息

App / 后端负责：界面、配对、队列、记录、导出、权限、Supabase、平台适配层与设备归属映射。

硬件 / 平台负责：确认板卡、官方 SDK 构建和烧录、产品 PID、设备 SN、平台配网绑定、灯珠与触摸驱动、语音播放、SDK 上下行与设备日志。

双方一起确认：物模型参数、调用和回调格式、身份映射、断网补发、解绑失效、真机验收。

队友回传：板卡完整型号 / 修订号、平台产品 PID 和设备 SN、固件与 SDK 版本、负责人的名字、已通过的检查项、脱敏的控制与事件报文、平台接口文档链接。**不要在表单 / GitHub / 群聊发送 PID SECRET、设备 key、数据库密码、Supabase 服务端密钥或账号验证码。** 需要的凭据在各自本地或受控服务器配置。

## 从哪一步开始联调

所有项目最初均为“未验收”，按实际结果打勾；软件协议测试不代替真机结果。

1. 按板卡官方示例烧录，平台 / 小程序出现真实设备在线，保留日志。
2. 平台控制面板开关真实灯，确认物模型标识和执行反馈。先确认灯能否显示所需颜色；若只有冷暖白灯，需外接兼容 RGB 灯或明确降级，不能宣称彩色灯语已实现。
3. 实现余光与平台设备的归属映射与适配层。账号 A 发心意，必须在平台日志看到控制下发，账号 B 的真机亮一轮并淡出。
4. 真机短触 → 平台事件 → 余光主动回应，A 才显示“收到啦”；单纯设备接收不能变已读。重复同一事件不增加回执。
5. B 专注 / 关灯时不点新情感光；退出后按队列顺序和冷却规则继续，不能瞬间连闪。
6. 长触 5 秒只开始休息，不同时回应心意；注意避开官方 SDK 配网复位按键既有手势（例如 XJWB03 文档 GPIO14 的长按复位）。
7. 断网重连不重播已完成指令；单方解绑后新灯语、旧音频都不可再访问。区分“亲友解绑”与“平台设备解绑”，不要无意解绑硬件产品。
8. 本人主动请求回听时才播放亲友原声，能停止；验证实际格式与解码。网页目前存原上传格式，没有自动转为板卡音频。赛事截图提到 PCM 16 kHz 单声道，XJWB03 示例描述 Opus 链路，两者不能混同；按最终板卡播放接口验证并补转码。
9. 桌搭开机后持续采集，实时结果只对本人显示；关闭 App 后仍自动分段保存，无信号显示等待，断网不冒用旧值。无传感器不展示虚假测量。个人引导练习计时仍可用。

建议两天顺序：第一天先完成 1–4 的最短真机闭环，第二天完成专注、重连、解绑和按需原声回听；呼吸采集取决于真实传感器。Agent 仅使用为实际交互所需的最小官方能力，不增加情绪诊断、摄像头或复杂 AI。

## 代码协作与发布

后续持续改代码用同一个 GitHub 仓库，加协作者后按功能分支提变更；ZIP 是本次快照，不会自动更新。业务源代码修改 `public/` 和 `shared/`，不单独改生成的 `hosting/`。修改后运行：

```sh
npm test
node --test hosting/tests/cloud.test.mjs
npm run check:sync
```

代码 push 到 GitHub 不等于发布网站，Sites 发布需另外构建部署，见 [在线部署](在线部署.md)。新成员只需跑本地 SQLite，不需要先取得组织的 Supabase 服务端权限。

交接包只包含版本化源码和说明，不包含真实账号、数据库、录音、缓存、`.env`、Git 登录信息和设备密钥。
