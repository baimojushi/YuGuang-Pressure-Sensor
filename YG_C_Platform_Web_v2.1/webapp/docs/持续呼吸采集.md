# 桌搭持续呼吸采集 · 接入约定

2026-10-30 用户确认：产品是桌搭，开机后持续采集，不依赖抱住、触摸或 App 点开始。亲友灯语、专注 / 情感光开关、自由休息不能默认停止传感器任务。实际传感器、测量范围、算法 / 模型及板卡尚待硬件同学确认；没有接上真机就不宣称已经测到呼吸。

## 当前实现

App「呼吸与互动 → 我的呼吸」顶部增加「此刻的呼吸」。后台接收设备持续计算的每分钟呼吸频率，页面约每 2.2 秒读取本人的结果，显示频率趋势和最后采样时间。只有设备主人的登录可以读取，不因亲友配对共享。网络失败、无信号、暂停或超过 15 秒无新数据时，当前值显示为 `—`，不沿用旧值。图表保留最近收到的趋势，颜色变淡；它不代表逐次吸气 / 呼气波形。

持续采集是固件常驻任务；本次完成的是接收、显示与保存能力，不是远程启动尚未接入的传感器。App、浏览器关闭后，设备仍可通过有网络的链路上报，服务端仍能保存；设备离线时需自己缓存历史。当前软件链路已实现，灵机平台的设备绑定、SDK、事件回调与权限映射仍待适配，不能用直连本接口代替比赛的平台闭环。

## 设备上报

`POST /api/hardware/<deviceId>/breathing/live`

鉴权：`X-Device-Key`；JSON Content-Type。设备密钥与现有硬件接口一致，轮换后旧 key 立即失效。平台适配层必须在服务端核验平台回调与设备归属，不能开放匿名转发。

字段：

| 字段 | 约束 |
| --- | --- |
| eventId | 唯一非空编号，最长 100 字符，重试保持一致 |
| measuredAt | 本次测量的 UTC 毫秒，校准时钟；不早于接收时刻 30 秒，不晚于 5 秒 |
| status | tracking / no_signal / paused |
| rpm | tracking 时必填，有限数，大于 0 且不超过 120；这是传输范围，不是健康判定 |

no_signal 表示设备运行但没有有效呼吸结果；paused 表示固件暂停传感器。这两种状态省略 rpm 或填 null，不能用 0 或上次值。无需给 App 添加“开始采集”按钮。设备断电、断网后无新上报，服务端派生为 stale。

建议每 2 秒发送一次有效结果，最多每秒一次，否则 429。相同已记住的 eventId 与相同内容重试不重复保存；内容冲突返回 409。保留最近 32 个事件去重，实时结果必须按 measuredAt 严格递增；迟到的离线历史请走原 `/breathing` 分段接口，不反过来覆盖当前值。不要每次重传生成新 eventId。

为了避免交接时误写假数据，这里不提供固定 rpm / 时间戳的可执行样本。请求模板中的时间和频率变量必须填实际采样结果。

## 本人读取

`GET /api/breathing/live`，沿用本人登录认证，忽略传入的其他 userId。

响应包含 status、rpm、measuredAt、receivedAt、serverNow、staleAfterMs，以及 `points: [{at, rpm}]`。无信号点的 rpm 为 null。返回的趋势明确为 `trendKind: frequency`；不接受“由灯光动画推算”的数据，也不输出情绪标签。状态可为 unbound、waiting、tracking、no_signal、paused、stale。

## 自动留存与容量

无需手动开始 / 结束，每个设备按 UTC 五分钟窗口自动生成一条设备记录。窗口内每 30 秒保留最后一个真实频率点，保留它实际采样时间；不补造缺失数据。第一条从首次有效采样开始记录，不将窗口之前的空白算作已测量。每条最多十个降采样点，更新末次采样时间与平均 / 最小 / 最大值。界面将这类记录标成「自动分段」，未完成的当前窗口也可回看；平均值是保留点的算术均值，不是逐秒连续测量均值。

实时趋势只保留最近五分钟、最多 150 个结果；这不等于原始传感器波形长期存储。已有本人记录查询 / CSV 导出包含自动分段记录；无信号时不新造有效采样。页面约 30 秒自动刷新归档记录。

当前仍是黑客松的单空间 CAS 状态结构，整个空间上限 8 MiB。持续写入不代表无限保存；容量满会明确报错，事务不落半份数据，不自动删除个人历史。长期运行前需改成逐条时间序列存储并协商保留周期；固件遇 429 / 存储错误应退避、告警，不高频重试。现有重传、原声和历史接口保持兼容，不需要数据库迁移。

## 还需要队友提供

1. 持续采集所用传感器、覆盖距离 / 角度、板卡型号和硬件常驻任务。
2. 模型或算法的输入、输出、更新周期；当前约定接已计算 rpm。原始波形、吸气 / 呼气阶段、灯光映射规则尚未收到，不猜测。
3. 无人 / 无效信号判定与异常处理；不将持续开机等同于始终能检测到本人呼吸。
4. 灵机 SDK 事件与物模型标识、平台回调规范，遵守比赛的真实平台链路。

验收需真实设备持续上报：开着 App 看更新 → 关闭 App 一段时间 → 再打开看自动记录 → 无信号不冒用旧值 → 断网恢复 → 换设备密钥后旧 key 拒绝 → 亲友看不到本人的采样。软件测试只验证协议，不代替这条真机验收。
