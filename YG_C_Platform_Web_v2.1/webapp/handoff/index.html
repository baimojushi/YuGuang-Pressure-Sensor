01 · 队友从这里开始

先跑 App

进入包里的 yuguang 文件夹，安装 Node.js 22.13+，执行：

npm ci
npm start

打开 localhost:3100。新包默认本机 SQLite，正式数据为空，不需要数据库密码。

再认板卡

查看板上型号与修订号，选择对应官方 SDK；先跑官方联网、绑定和控制示例，再接余光逻辑。

本包不含官方 SDK、任何账号资料或真实密钥。GitHub 仓库目前私有，ZIP 可以直接发给队友。

完整交接说明余光设备协议 v2持续采集约定下载 Postman 请求模板

02 · 确认接入路线

亲友 App → 余光后端 / 队列 → 待开发的平台适配层 → 灵机平台 → 官方 SDK → 真机灯效
真机触摸 → 平台事件 → 余光后端 → 亲友主动回应

服务端保留配对、队列和权限，硬件执行一轮灯语后淡出。设备接受指令只代表执行确认；用户主动触摸才代表“收到啦”。

平台侧要补什么
  • 产品 PID、物模型、设备 SN 与余光设备归属的安全映射。
  • 取得真实设备控制接口与鉴权规范，后端封装平台调用。
  • 平台事件回调验签、防重放、去重与解绑失效处理。
  • 固件灯效、触摸、防抖、长短触互斥和断网补发。
  • 原声播放解码 / 转码；目前网页保存上传格式，并未转换为板卡格式。
手册与候选 SDK（先确认型号）
  • 官方设备开发手册 · 快速上手 · 灵机开放平台
  • 物模型 / 设备接入 · 平台能力集成与回调
  • XJWB03 / ESP32-S3：官方 SDK，需按文档克隆子模块。
  • LJWB130 / AC7911B：官方 SDK，工具链与 ESP32 不同。

文档目录包含多种板卡，尚未确认你们实物的型号。这里没有虚构平台 API URL，也没有将项目字段当作平台官方标识。

给硬件同学的最短接口说明

以下都是余光自己的 API。正式基址为网站地址加 /api，本地为 http://localhost:3100/api；带 X-Device-Key，设备主人在“我的余光”生成设备编号和一次性 key。不要写入前端、Git 或进度 JSON。

方法 / 路径用途
POST /hardware/{id}/heartbeat约 10 秒心跳，读取停止 / 专注状态
GET /hardware/{id}/pending约 2 秒查询灯语与休息
POST /hardware/{id}/breathing/live开机持续上报呼吸结果，自动分段保存
POST /hardware/{id}/deliveredcommandId 确认接受执行
POST /hardware/{id}/gestureeventId + 短触 / 长触，互斥、幂等
PUT /hardware/{id}/focusfocus 布尔值
GET /hardware/{id}/messages、/audio/{audioId}本人主动查询 / 回听原声

在电脑调用这些接口会改变真实设备记录，但不能证明灵机链路已通。请先使用本地测试账号；比赛最终链路必须经平台。
