# 余光平台侧适配定义（对应契约 YG-IFACE-2.1.0）

适用范围：灵机云（物模型 + 灵机面板）与 Web 平台（Web App + Supabase）。
不覆盖：业务板/感知板固件内部实现（见各自固件基线）。
条款引用格式：`契约 §N`。

## 1. 数据流分层与平台边界

```text
[感知板 B] --BLE 5-10Hz--> [业务板 A] --MQTT--> [灵机云] --桥--> [Web App/Supabase]
  雷达/姿态/融合引擎           物模型/语音/灯/GPIO5     ↑平台侧A   ↑平台侧B
                                                    (灵机面板)  (伴侣端+本人Web)
Demo 姿态云推理: B --HTTPS--> [云端姿态API]（临时、独立授权、不接消息业务）
```

边界规则（契约 §3）：

- Breath Stream（BLE 5-10Hz）不上云；业务板本地插值与平滑驱动 LED 动画，数据超过 1500ms 视为过期，持续 3000ms 无有效数据退出真实呼吸同步。
- 压力回落事件（`pressure_fall_start`）在业务板本地消费，不触发云平台消息。
- 10.3 上云初始策略：最短上报间隔 10 秒；变化阈值 0.5 次/分钟；有效数据保活 60 秒；无有效数据立即置 10.4=no_signal。
- 10.3 仅设备所有者本人可查；伴侣端无读取权限、不展示。
- 感知板原始雷达波形、姿态关键点、压力回落事件、融合分值及各分项评分：正式模式均不上云。
- 研发期允许经授权的独立 /dev 调试通道，但必须与普通用户和伴侣权限隔离（P2+）。

## 2. 物模型差量

### 2.1 保留属性（标识与类型不变，面板零改动）

| 属性 | V2.1 下语义 | 面板影响 |
|---|---|---|
| 9.1 情感光开关 | 不变（亲友心意灯效许可） | 无 |
| 10.2 专注 | 不变（用户主动切换；新增约束：专注中回落事件被门控） | 无 |
| 10.3 呼吸频率 | 细化为 **Measured Breath**（真实测量节律） | 无（显示逻辑原样成立） |
| 10.4 采集状态 | 保持 ok/no_signal 二值；细粒度状态（雷达/视觉/推理分项）走 /dev，不上云 | 无 |

### 2.2 新增 siid 13（六属性，录入用 JSON 见 `thing_model/siid13_proposal.json`）

| piid | 名称 | 类型/权限 | 默认 | H5 数据键 | 阶段 |
|---|---|---|---|---|---|
| 13.1 | 随息陪伴开关 | bool，rw | true | `suixi_SuixiSwitch` | P1 |
| 13.2 | 引导状态 | string，ro | idle | `suixi_GuideState` | P1 |
| 13.3 | 引导目标周期 | uint16，ro（100ms 单位，0=无有效引导目标） | 0 | `suixi_GuidePeriod` | P2 |
| 13.4 | Demo 云推理启用意向 | bool，rw | false | `suixi_CloudPoseOptIn` | P3 |
| 13.5 | 感知板连接状态 | string，ro | lost | `suixi_SensorLink` | P1 |
| 13.6 | 主动放松请求 | bool，瞬时写入并自清 | false | `suixi_RelaxRequest` | P1 |

语义要点：

- H5 数据键 = `{serviceName}_{description}`（serviceName=`suixi`），与既有四键同一生成规则。
- 13.6 仅在业务板尚未进入同步或引导状态时接受新启动意图，执行后固件写回 false；固件需限制重复启动。
- 13.4=true 只表达平台侧启用意向；感知板须同时具备本地授权与合法 API 配置才实际发送去隐私姿态特征。
- 13.2 对外值固定 `idle / syncing / guiding / cooldown`；状态机 6 态明细仅走 /dev。
- 13.5 对外值固定 `connected / lost / negotiating`。

## 4. 云端与 Web App 适配

### 4.1 「收到了」回执链路（P0 末/P1，平台侧最大单项）

```text
[业务板] GPIO5 确认（仅 CARE_ACK_ARMED 且亲友灯效展示中）
  → method_up：care_ack 负载（care_ack.schema.json，含 event_id/message_id）
  → 灵机云桥接服务【新增】：验签 + 消息归属校验 + message_id 幂等 + 原子状态更新
  → Supabase（消息记录 acknowledged_at 置位）
  → 发送者页面实时更新
```

硬性要求（契约 §4）：

- 每个消息 ID 仅一次有效确认事务；网络失败重试必须复用原 event_id，不得重建确认。
- 平台桥接服务负责验签、验证消息归属、去重与 Supabase 原子更新；收到服务端确认后，业务板才将该回执标记为已完成。
- 灵机云 MQTT 主题、method_up 包络字段及回调签名以现有 SDK 和基线实现为准，不得猜测平台私有字段；上述 JSON 为三端共享的业务语义负载。
- 日常随息灯光、普通氛围灯、冥想灯效期间的红外触发**不得**产生回执（契约 §3.2 门控）。

### 4.2 Web App 改动

| 项 | 改动 | 阶段 |
|---|---|---|
| 发送者端回执展示 | 心意消息增加「已收到」状态（依赖桥接服务） | P1 |
| Supabase 消息表 | 增加 acknowledged_at 字段 | P1 |
| 接收者端 | 不展示任何生理数据（V2.1 产品定位：不把生理数据展示给伴侣） | 贯穿 |
| 休息/冥想/心意 flows | 不变（语音与触摸在设备本地，云端单设备视角不变） | — |

## 5. 研发控制面板（/dev）

归属建议：Sites 独立路由（授权保护、仅开发者账号）或业务板串口直出 PC 工具；**不进灵机用户面板**。

内容（P2-P4）：BLE 连接/订阅/丢包状态；LD6002 原始相位及滤波波形；Measured vs Guidance 双曲线；姿态/呼吸/专注三指标；融合权重与趋势事件；GPIO5 触发时间、消息窗口及回执；Demo API 调用记录。

量产移除上云通道（感知数据默认留在端侧）。

## 6. P0-P4 平台侧适配时序

| 阶段 | 平台侧动作 | 关联验收（契约 §12） |
|---|---|---|
| P0 | 现有 v2 够用，零新增；回执可只验证固件本地幂等 | 红外只在亲友灯效期间确认；每消息只回复一次；两板重启自动重连 |
| P1 | siid 13.1/13.2/13.5/13.6 上平台；面板随息卡片 + 设备设置卡；回执桥接服务上线 | 灯光稳定跟随真实呼吸，失数据无随机闪烁 |
| P2 | 13.3 上平台；/dev 双曲线面板 | 先跟随再渐进放慢，未跟随时重新同步 |
| P3 | 13.4 上平台 + 授权 UI | 三指标有量纲/基线/质量控制/可复现融合 |
| P4 | /dev 回落事件记录 | 回落准确性、误触发率、触发延迟 |

## 7. 固件两侧基线衔接（参考，详见各自固件基线）

- **业务板** = 现 vb701n 工程 − `peripheral/radar_*` − `pose/` + BLE Central（NimBLE）+ GPIO5 门控状态机；`iot_control` 查表与影子回报**原样保留**，`iot_control_breath` 数据源从本板雷达快照改为 BLE Breath Stream 订阅缓存——**上报接口不变，这是面板零改动的保证**。
- **感知板** = 新工程 = `radar_ld6002 + radar_resp_filter_v8 + pose/yolo11 + 融合引擎 + BLE Peripheral`（自现仓库迁出）；**不包含** cloud/、iot_control、voice/。
- 融合引擎（S=0.40R+0.35P+0.25F，基线归一化+质量降权，信息不足输出「无法判断」）落 `FALLING_START` → BLE Pressure Event；`GUIDED_RECOVERY` 由业务板主导，感知板持续供相位数据。
